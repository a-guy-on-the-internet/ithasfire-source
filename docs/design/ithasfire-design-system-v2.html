The Foundation

Every component on this page is built from semantic tokens only — no raw hex outside the token block. Flip the theme toggle above: the entire system reskins between the Ember (dark) and Stub (light) palettes. Choosing a final palette later is a one-variable decision, not a rebuild. Stub is the shipped default.

01.

Token Architecture

Three tiers. Primitive tokens hold raw values (hex, px). Semantic tokens map primitives to meaning (--color-accent, --sp-5). Component styles consume semantic tokens only. Themes redefine the semantic layer; components never change. The code uses different token names — see design-system-v2.md for the mapping.

02.

Flex vs Grid — Strict Rules

One question decides it: do columns need to align across rows? Yes → Grid. No → Flex. Everything else follows from that.

ContextUsePattern
Card collectionsGRIDgrid-template-columns:repeat(auto-fill,minmax(272px,1fr)) — never media-query column counts for cards; let minmax do it.
Multi-column page regionsGRIDExplicit fr ratios, asymmetric on purpose: grid-template-columns:7fr 5fr. Never 50/50 unless content is truly equal.
Table-like rows (lineup, stub)GRIDFixed first/last tracks, fluid middle: 110px 1fr auto auto. Guarantees column alignment across every row.
Nav bars, button rows, chipsFLEXdisplay:flex;gap:var(--sp-2). Content-sized, wraps naturally.
Card internals (vertical stack)FLEXflex-direction:column + margin-top:auto to pin footers. Cards must be equal-height siblings inside the grid.
Meta lists, icon+label pairsFLEXRow flex, align-items:center, gap only.
Spacing between siblingsGAPNEVER margins between siblings. Gap only, always from the spacing scale. Margins exist only for margin:auto pinning.
Nesting—Grid for the skeleton, flex for the flesh. Never a grid inside a grid to fake a row; never flex-basis percentages to fake columns.
Containers—Content: 1200px. Full-bleed chrome (footer, CTA bands): 1440px. Side padding: --sp-6 desktop, --sp-4 mobile.
Breakpoints—480 / 640 / 900 / 1200. Grids collapse by re-declaring grid-template-columns — never by hiding content.
03.

Buttons

Three variants, three sizes, four icon positions. A page gets exactly one primary button per viewport. If two actions compete, one of them is secondary — decide, don't hedge.

Variants × sizes

Primary — accent fill1 per viewport max
Secondary — structure outlineFills on hover
Ghost — chrome & tertiary actionsNav, cancel, less-important

Icon rules

Icon placement — the grammar
RuleSpec
Trailing iconReserved for direction and progression only — arrows, external-link, chevron. "This takes you somewhere."
Leading iconReserved for objects and context — ticket, calendar, user, search. "This is about a thing."
Never bothOne icon max per button. An icon on each side reads as decoration, not meaning.
Icon sizesm: 13px · md: 15px · lg: 16px viewBox render. Lucide set only, stroke-width 2 (2.5 for arrows). No mixed icon sets.
ColorAlways stroke="currentColor". Icons never carry their own color.
Gap--sp-2 (8px) between icon and label at all sizes.
Icon-onlySquare (width = height), aria-label required, minimum 44×44 touch target at md. Only for universally understood glyphs: search, close, menu.
Label caseUPPERCASE, +1.5px tracking, weight 700. 1–3 words. Verbs first: "Get Tickets," never "Tickets Here."

07.

Sections & Hierarchy

The section vocabulary. Every page is assembled from these, in slot order, with index numbers (Montserrat 700, tabular-nums) assigned top to bottom. Slots: S1 Open → S2 Signal → S3 Discover → S4 Browse → S5 Proof → S6 Convert → S7 Close. A page may skip slots but never reorder them.

Display type left, live data rail right. The rail earns its space with real numbers (event count, trending, scans).

08.

Page Assembly — Home

The canonical home template. Slots in order, indices assigned after assembly. Rules of composition: exactly one S1, S6 is mandatory on marketing pages, only one accent-dominant band per page (S2 or S6's panel — not both at full strength).

NAV — BRAND · SEARCH · SIGN IN · CREATE EVENT
S1 · OPEN — HERO (SPLIT+RAIL or STATEMENT+SEARCH OBJECT)
S2 · SIGNAL — MARQUEE (OPTIONAL)
S3 · DISCOVER — IDX 02 · POPULAR EVENTS + FILTERS
S4 · BROWSE — IDX 03 · CATEGORY (OPTIONAL)
S5 · PROOF — STATS BAND (OPTIONAL)
S6 · CONVERT — IDX 04 · HOST CTA
S7 · CLOSE — IDX 05 · FOOTER

Login is chrome, not a slot: it lives in the nav as a ghost button opening the auth modal, and reappears wherever an action requires an account (S6 button when logged out).
